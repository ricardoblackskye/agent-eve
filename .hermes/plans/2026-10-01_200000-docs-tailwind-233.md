# Tailwind CSS adoption for documentation pages (#233)

**Branch:** `feat/docs-tailwind-232a` (off `origin/main`)
**Issue:** #233 — leg 1 of 6 under #232
**Blocks:** #234 (docs site), and every later leg that styles a page

## Goal

Make Tailwind available for documentation pages, with the scope decision recorded
as an ADR, without changing how the existing application looks.

## Phase 1 assessment (the "we can assess that" pass)

Measured, not assumed:

| Question | Finding |
|---|---|
| How many styled pages? | **7** — `/`, `/architecture`, `/dark-factory`, `/dark-factory/runs`, `/dark-factory/runs/[runId]`, `/releasenotes`, `/unauthorized` (plus 16 `route.ts`, unstyled) |
| Existing styling surface | `app/globals.css` — 145 rule lines, **97 distinct class selectors** |
| Tailwind present? | No — nothing in `package.json`, no `tailwind.config.*`, no `postcss.config.*` |
| Does the app already reset? | **Yes** — `* { box-sizing: border-box; margin: 0; padding: 0 }` at the top of `globals.css` |
| Explicit `h1`–`h6` / `p` / `ul` / `li` rules? | **None** — only `body` |
| e2e assertions on classes | `architecture.spec.ts`: `.mermaid-wrapper svg` (count **6**), `h2:has-text(…) + .mermaid-wrapper svg`, `pre.mermaid` (count 0). `chat.spec.ts`: `.status` + **`toHaveCSS("background-color", …)`**, `.message.user`, `.message.assistant p`, `.error-message` |

### What this means

**Preflight's margin resets are largely a no-op here** — the app already zeroes
`margin` and `padding` on every element with its own reset. Likewise its
`box-sizing` normalisation. So the bulk of Preflight's blast radius does not
apply.

**The one real regression is headings.** Preflight sets
`h1`–`h6 { font-size: inherit; font-weight: inherit }`. Because `globals.css`
defines no heading rules, every heading in the app currently renders at the
**browser default** size and weight — so Preflight would shrink all of them to
body text across all 7 pages. Lists would also lose their bullets
(`list-style: none`), and Preflight's `border-style: solid; border-width: 0`
default could affect any element relying on UA border defaults.

**Computed-style assertions are unaffected** — Preflight resets layout, not paint,
so `chat.spec.ts`'s `background-color` assertion is safe.

### Recommendation

**Option (a), repo-wide** — the risk is now bounded and known rather than
open-ended, because the app's existing reset removes most of Preflight's effect.
The remaining work is small and specific: restore explicit heading (and list)
typography in `globals.css` so Preflight cannot flatten it, then prove the pages
are unchanged.

This supersedes my earlier lean toward docs-scoping, which was based on assuming a
larger blast radius than the measurement shows. If the heading work turns out to
be more than a few rules, fall back to (b) and record that instead — the ADR
captures whichever we land on.

## Intended fix

1. Add Tailwind v4 (CSS-first: `@import "tailwindcss"` in `globals.css`; no JS
   config needed) and `@tailwindcss/typography` for the `prose` class.
2. Restore heading and list typography explicitly in `globals.css`, so Preflight's
   `font-size: inherit` / `list-style: none` resets cannot flatten them.
3. Record the scope decision, and the seam between Tailwind and the existing plain
   CSS, as an **ADR** (`docs/adr/0009-…`) — required by the workflow, and the
   issue's own acceptance criterion.
4. Leave the 97 existing class selectors untouched: they remain the styling for
   existing pages.

## TDD

This is a build-configuration change: there is no runtime behaviour to drive. Per
the workflow, a behaviour-preserving config change uses a structural anchor plus
the existing suite as the regression oracle.

**RED** — `tests/tailwind-config.test.ts` asserting:
- `app/globals.css` imports Tailwind;
- `@tailwindcss/typography` is a declared dependency;
- `package.json` carries the Tailwind packages.

Run it: every assertion must fail because Tailwind is absent — not because a file
cannot be read.

**Regression oracle** — the *actual* risk is headings flattening, so add a guard
that fails if they do. Extend `e2e/architecture.spec.ts` (or add a sibling spec)
asserting a rendered `h2` computes a **larger font-size than body text** on an
existing page. It passes today via UA defaults and must still pass afterwards —
which is exactly what makes it a meaningful guard rather than decoration.

**GREEN** — add Tailwind, the typography plugin, and the explicit heading/list
rules.

**REFACTOR** — keep the Tailwind import and the reset adjacent and commented, so
the seam is obvious to the next reader.

## Risks / open questions

- **`npm run build` is the real gate, not just the test suite.** A Tailwind/PostCSS
  misconfiguration fails at build, so a green unit suite is not sufficient
  evidence for this leg.
- **Preflight is the whole risk.** If heading/list restoration is not clean, switch
  to option (b) (docs-scoped, Preflight disabled) and record *that* in the ADR —
  including why (a) was rejected, which is itself valuable.
- **The e2e count assertion.** `architecture.spec.ts` pins `.mermaid-wrapper svg`
  to **6**. This leg adds no diagrams, so it should stay green — but #234 changes
  it, and the two must not collide. Flagging rather than fixing here, to keep this
  leg's diff honest.
- **Two styling systems.** Even with option (a), the 97 existing selectors remain
  hand-written. The ADR must state the intended end state, or "we'll migrate later"
  becomes permanent.
- **Playwright needs a running server**; confirm the repo's e2e invocation before
  claiming the visual guard passes.

## Out of scope

The `/documentation` route and any page content (#234). Restyling existing pages
beyond what Preflight forces.
