# An empty fix pass is retried once and reported (#756)

**Issue:** [agent-eve#756](https://github.com/ricardoblackskye/agent-eve/issues/756) (`bug`, deferred, follow-up)
**Branch:** `fix/756-empty-fix-pass`
**Status:** RED and GREEN committed and pushed. This document was written **after** the implementation - the note
at the bottom says why that happened and what it costs.

**Goal:** make an empty fix pass - no files authored, no reasons given - distinguishable from having made no attempt
at all, by retrying it once and then saying so on the record.

---

## Context

Observed live on WebFeedPOC `#262` and `#264`, and again on `#266`: three consecutive passes, each logging

```text
Fix cycle   prepared 'feat/dark-factory-266' in a sandbox for run ...
Fix cycle   authored 0 file(s) for 1 finding(s)
```

against a ticket that showed only a bare `df:blocked`. The module's own documentation names why that is the
defect: *"a pass that tried fifty findings and reported nothing would be indistinguishable from one that tried
none"* - and that is equally true of a single finding.

The code path, read at `agent/lib/dark-factory/fix-cycle.ts`: `runPass` produces dispositions only from
`changedFiles.length > 0`, and then from explained refusals. A pass with neither therefore returns `[]` - nothing
resolved, nothing explained, nothing retried, and nothing logged.

## Approach

In `runPass`, after the first authoring call: if the result has **no changed files and no refusals**, retry the
authoring call **once**. If the retry is also empty, log that nothing was produced and why it cannot be told apart
from no attempt, and return no dispositions.

The retry is **bounded**, matching every other ceiling in this module (`DF_MAX_PLAN_REVISIONS`, the
`failed-selfcorrect-exceeded` cap): one retry, never a loop. An empty pass is plausibly transient - a model that
returned nothing once may return work on a second attempt - so one retry buys the cheap case and the second empty
pass is then reported rather than swallowed.

## Scope - stated explicitly

**The issue has two acceptance lines and this change satisfies only the second.**

| acceptance line                                                                  | status                                                        |
|:---------------------------------------------------------------------------------|:--------------------------------------------------------------|
| *a finding that no code change can address does not enter the authoring cycle*   | **NOT implemented.** The finding still enters the cycle.      |
| *if it does, one author-nothing pass ends it, with a stop reason that names why* | **implemented** - bounded at a retry, and the stop is logged. |

Two further notes so the record is not overstated:

- The issue's wording (*"one author-nothing pass ends it"*) reads as a single pass; this change allows **one
  retry**, so it takes **two** author calls before stopping. That is what the parked RED specifies
  (`expect(h.author).toHaveBeenCalledTimes(2)`, described as *"a retry, not a loop"*), not drift from it.
- Classifying an unactionable finding **before** dispatch belongs with #743's work on surfacing a finding's root
  cause and owner, where the classification has somewhere to live.

## Files

- `agent/lib/dark-factory/fix-cycle.ts` - the retry and the report, in `runPass`.
- `tests/dark-factory/fix-cycle-empty-pass-756.test.ts` - the RED, with the control.

## Verification

- The RED's three cases: an empty pass is retried (2 author calls, 1 push, the finding resolved); a second empty
  pass stops the pass and logs (2 author calls, `dispositions` empty, the log matching
  `/no change|produced nothing|authored nothing/i`); and **the control** - a pass that authored a file is NOT
  retried (1 author call).
- `tsc --noEmit` exit 0.
- Full suite in the gate's mode with the six `DF_*_TEST_DATABASE_URL` set: **430 files passed, 3916 passed,
  0 failed**.
- Coverage ratchet: exit 0. Two metrics moved by -0.01/-0.02pp, inside `DEFAULT_TOLERANCE_PCT` (0.05), which
  exists to absorb exactly this - so this passes rather than failing on rounding.

## Risks

- **A retry doubles the authoring cost of a genuinely empty pass.** Bounded at one, and only on the empty path, so
  the cost is one extra authoring call per empty pass rather than per finding.
- **The report is a log line, not a ledger field.** An operator reading the run ledger still cannot distinguish the
  two cases; only the run's log can. Persisting it is #716/#704 territory (run summaries and run details).
