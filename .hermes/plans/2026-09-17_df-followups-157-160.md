## #160 — full TDD detail (this branch)

### Root cause

Two independent weaknesses in `agent/lib/dark-factory/index.ts`:

1. `resolveStateDbPath(rawPath, sandboxRoot)` returns the lexical `resolve(rawPath)` once
   `path.relative` says it is inside the root. `path.relative` is string maths: a **symlink** placed
   inside `DF_STATE_DB_DIR` that points outside it passes the check, and the SQLite file is then opened
   outside the intended root.
2. `readInt` coerces with `Number()` and validates `Number.isInteger`, so scientific notation (`1e3`)
   and other coercible forms are accepted, and there is **no upper bound** — `DF_DISPATCH_MAX_RETRIES`
   can be `Number.MAX_SAFE_INTEGER`.

### Fix (mirrors `applySkeletalMap`, proven in #153)

- Reject coercible-but-not-plain-digit input with a **digits-only** check, and add a documented
  **maximum** per variable, failing as a named configuration error.
- For containment: after the lexical check, resolve the **real** path of the deepest **existing**
  ancestor and re-check containment against `realpath(sandboxRoot)`. A not-yet-created database file has
  no real path of its own, so the ancestor walk is what makes this testable — and refusing an escaping
  symlink must happen **before** any store is opened.
- Keep `path.relative` for the containment decision (not a `startsWith` prefix compare): it follows the
  platform's case sensitivity, which is why a drive-letter case difference is not a false rejection.

### Tasks (RED → GREEN, one behaviour per cycle)

| # | RED (failing test first) | GREEN |
| --- | --- | --- |
| 1 | a symlink inside `DF_STATE_DB_DIR` pointing outside ⇒ REFUSED, naming the symlink | realpath ancestor walk + containment re-check |
| 2 | a legitimate path (incl. differing drive-letter case) ⇒ accepted, no false rejection | unchanged `path.relative` path |
| 3 | a not-yet-created db file under the root ⇒ accepted (ancestor walk handles it) | walk to nearest existing ancestor |
| 4 | no `DF_STATE_DB_DIR` ⇒ path used as-is (lexical only, as today) | unchanged default |
| 5 | `DF_DISPATCH_MAX_RETRIES="1e3"` ⇒ throws, naming the variable | digits-only validation |
| 6 | a value above the documented maximum ⇒ throws naming the maximum | bound check |
| 7 | a valid plain-digit value ⇒ parsed, and existing dispatch tests unchanged | unchanged accept path |
