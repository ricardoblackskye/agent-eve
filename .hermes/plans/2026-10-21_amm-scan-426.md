# #426 — the AMM scanner: produce real measurements instead of fixtures

**Release split (agreed):** **R1 + R2 in ONE PR** on `feat/amm-scan-426`. **R3 (sandbox execution of the command checks) stays out** — local-sandbox-only when we do it. This PR covers AC1, AC2, AC4, AC6.

## DECISIONS AGREED (2026-10-21)

1. **The catalogues and the scans must be GENERIC.** A scan runs against repositories other than this one, so the catalogue may not hard-code one repository's layout. Repo-specific locations move OUT of the catalogue into a per-repo **layout**. A signal the layout does not address is **`unmeasured`, never `absent`** — we never looked, so we cannot report having looked and found nothing.
2. **The narrowed claims are accepted.** Where a check proves less than its label claims, the row's claim narrows to what the check actually shows. **Such rows are marked `weak` with a reason** rather than left over-claiming silently.
3. **`containerized-build` stays a root-`Dockerfile` existence check.** This repository therefore reports it genuinely `absent`: its only Dockerfile builds the *sandbox image*, not the repository. Correct under the generic reading.
4. **`persistent-sessions` is a real product gap, not a catalogue bug** → recorded as **#430**. The scanner reporting it absent is CORRECT; the work is the feature, or retiring the row.
5. **The 3 GitHub vulnerabilities are parked** — not this PR.

## What this PR delivers

Every AMM figure in the product comes from a fixture today (`fixtureAmmProvider()`, `amm-readiness.ts:295`). #382 built the model and #424 built the storage; both stopped at the edge of I/O. This PR produces the measurements.

- **R1** — every one of the 39 catalogue rows carries a machine-checkable expectation, and the catalogue stops encoding this repository's layout (AC1).
- **R2** — `runAmmScan({ repo, workspace })` evaluates those expectations and returns an `AmmScan` via `scoreRepo()`, stamped with the catalogue version (AC2, AC4, AC6), invoked by `npm run df:amm-scan`.

## R1 — vocabulary + a generic catalogue (AC1)

**Files:** `agent/lib/dark-factory/amm-signals.ts`, new `agent/lib/dark-factory/amm-layout.ts`, `tests/dark-factory/amm-scoring.test.ts`

```ts
/** What a check must show for its signal to count as PRESENT. Replaces the prose `expected` (#426 AC1). */
export type AmmExpectation =
  | { kind: "exists" }
  | { kind: "contains"; text: string }
  | { kind: "exitCode"; code: number; withinMs?: number };
```

**The catalogue declares WHAT; a layout declares WHERE.** A `file` check's path becomes optional:

```ts
export type AmmSignalCheck =
  | { kind: "file"; path?: string }   // omitted: the repository's layout must supply one
  | { kind: "command"; command: string };
```

- Generic rows keep a conventional path (`.cspell.json`, `Dockerfile`, `tests/`, `package.json`, …) that applies to any repository.
- The nine rows above carry **no path** — the catalogue stops pretending to know another repository's layout.
- `amm-layout.ts` exports `AmmRepoLayout` (`signal id -> path`, relative to the repository root) plus a layout for the reference repository, which supplies the nine paths **with the three wrong ones corrected**.

Tasks:
1. Add the vocabulary; replace `expected: string` with `expectation: AmmExpectation` across all 39 rows; narrow the six claims; add `weak?: string` where a check under-verifies its label.
2. Give the two time-bounded rows `withinMs` (30000, 120000) rather than a bare exit code.
3. Remove the nine hard-coded paths; add `amm-layout.ts` with the reference layout and the three corrections.
4. **Extend the existing "names an automated check … for EVERY signal" test** (`amm-scoring.test.ts:42`) to assert, for every row: an `expectation` exists; its kind is compatible with the row's `check.kind` (`file` -> `exists`/`contains`, `command` -> `exitCode`); every `kind` used is in the vocabulary; and every `weak` row carries a reason. This is the test AC1 asks for.
5. Guard that every path-less `file` row is served by the reference layout — so a row cannot be added that no scan can ever measure.

Deliberately NOT in R1: the evaluators, which are R2.

## R2 — the runner (AC2, AC4, AC6)

**Files:** new `agent/lib/dark-factory/amm-scan-runner.ts`, new `scripts/amm-scan.ts`, `package.json`, new tests.

```ts
export interface RunAmmScanInput {
  repo: string;
  workspace: string;
  layout?: AmmRepoLayout;         // defaults to the reference layout when the repo matches it
  provider?: SandboxProvider;     // defaults to createRefusingSandboxProvider(...)
  now?: () => string;
}
export async function runAmmScan(input: RunAmmScanInput): Promise<AmmScan>;
```

One evaluator per expectation kind, everything resolved through `SandboxProvider.create(workspace)`:

| check | evaluation | yields |
|---|---|---|
| `file` + `exists` | resolve the path (layout, else the row's own); `listFiles` | `present` / `absent` |
| `file` + `contains` | `readFile` + substring | `present` / `absent` |
| `command` + `exitCode` | `runTests(cmd)`, timed | `present` / `absent` / **`unmeasured`** |

The three-state rule (AC2) is the point of the issue, so every path is pinned by a test:

- **`unmeasured`, never `absent`**, when: a path-less row has no layout entry (we never looked); the sandbox refuses (`SandboxRefusedError`); tooling is missing; a command exceeds `withinMs`; or the workspace cannot be read.
- **`absent`** only when the check genuinely ran and found nothing.
- A workspace that cannot be read at all -> every signal `unmeasured`, never a page of `absent`.

Then hand the measurements to `scoreRepo()` and stamp `catalogueVersion()` (`amm-signals.ts:552`).

CLI: `scripts/amm-scan.ts` + `npm run df:amm-scan -- --repo <name> --workspace <dir> [--layout <file>]`, printing the scan as JSON. Same `tsx` convention as `df:local-run`.

## Risks

- **`unmeasured` is load-bearing.** The dangerous failure is a command check reporting `absent` because the sandbox was down — the false negative AC2 exists to prevent. Tested directly.
- **A weak row reads as a strong one** unless `weak` is surfaced. It is catalogue metadata, not part of `AmmScan`, so the UI is unchanged (AC4) — but the PR body must list the weak rows and why, or the marker is decoration.
- **The reference layout is data, not truth.** If it drifts from the repository, this repository's own scan goes wrong. The guard catches a *missing* entry, not a stale one.
