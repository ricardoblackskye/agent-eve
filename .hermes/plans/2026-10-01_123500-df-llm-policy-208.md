# Dark Factory LLM Call Policy (#208) Implementation Plan

> **For Hermes:** implement task-by-task with `test-driven-development`
> (RED -> GREEN -> REFACTOR). This is release **R7.2** of epic #206, and it
> **absorbs #217** (the orchestrator gate) as agreed.

**Goal:** one canonical, provider-neutral LLM policy for **thinking level** and
**maximum steps**, applied to all three LLM surfaces — the orchestrator chat
model, the worker sandbox, and the PR review path — with the effective policy
visible read-only on the dashboard.

**Architecture:** a canonical `LlmPolicy` type with fail-closed env resolution,
a provider adapter that maps it to provider request parameters and degrades
gracefully where a model cannot reason, a non-secret sandbox env contract for the
worker (mirroring `worker-cost-env.ts`), and an opt-in `defineDynamic` conversion
of `agent/agent.ts` so the orchestrator can be both policy-shaped and cost-gated
per step.

**Tech Stack:** TypeScript, AI SDK / OpenRouter, `eve` (`defineAgent`,
`defineDynamic`), Vitest, Next.js App Router, plain CSS.

## Decisions (settled)

1. **The policy is env-driven, not DB-backed.** #208 is explicit: changing policy
   is a deploy. The DB-backed dynamic control is R7.1's off-switch, which is a
   different thing.
2. **Canonical type is provider-neutral.** `{ thinkingLevel, maxSteps, model? }`
   — no vendor fields. A provider change must not alter this shape.
3. **Fail-closed resolution.** Unset uses the documented default; malformed or
   out-of-range THROWS. Never a silent default (that is the exact failure mode
   this release exists to remove).
4. **Graceful degradation is reported, not hidden.** A model that cannot reason
   gets no reasoning parameters, and the adapter says so in its result so the
   dashboard can show the no-op rather than implying it applied.
5. **Opt-in orchestrator conversion.** When no policy and no cost gate are
   configured, `agent/agent.ts` returns the same static model as today. An
   unconfigured deployment is byte-for-byte unchanged.

## Decisions that need YOUR call before Task 5

6. **`maxSteps` precedence.** #208 says "replacing the scattered ad-hoc limits",
   but an outright replacement would silently change the behaviour of any
   deployment that has set `DF_MAX_ITERATIONS` or `DF_MAX_REVIEW_ROUNDS`.

   - **(a) Layered (recommended):** explicit per-surface `DF_MAX_*` > 
     `DF_LLM_MAX_STEPS` > built-in default. Nothing changes unless
     `DF_LLM_MAX_STEPS` is set, and the policy genuinely governs when it is.
   - **(b) Replacing:** `DF_LLM_MAX_STEPS` wins outright; the `DF_MAX_*` vars
     become deprecated aliases.

7. **`EnvConfigError` reuse.** #208 names `EnvConfigError` for malformed values.
   It already exists in `circuit-breaker.ts`.
   - **(a) Reuse (recommended):** import the existing class. Zero new surface,
     matches the issue's wording, but couples the policy module to
     `circuit-breaker.ts`.
   - **(b) Extract:** move it to a small shared `env-config.ts` and re-export
     from `circuit-breaker.ts` for compatibility. Cleaner, but touches a shipped
     module.

```ts
import { describe, expect, it } from "vitest";
import {
  DEFAULT_MAX_STEPS,
  DEFAULT_THINKING_LEVEL,
  resolveLlmPolicy,
  THINKING_LEVELS,
} from "../../agent/lib/dark-factory/llm-policy";

describe("resolveLlmPolicy", () => {
  it("applies documented defaults when nothing is set", () => {
    const policy = resolveLlmPolicy({});
    expect(policy.thinkingLevel).toBe(DEFAULT_THINKING_LEVEL);
    expect(policy.maxSteps).toBe(DEFAULT_MAX_STEPS);
    expect(policy).not.toHaveProperty("model");
  });

  it("accepts every supported thinking level", () => {
    for (const level of THINKING_LEVELS) {
      expect(resolveLlmPolicy({ DF_LLM_THINKING_LEVEL: level }).thinkingLevel).toBe(level);
    }
  });

  it("FAILS CLOSED on a malformed thinking level, never a silent default", () => {
    expect(() => resolveLlmPolicy({ DF_LLM_THINKING_LEVEL: "medium-high" })).toThrow(
      EnvConfigError,
    );
  });

  it("FAILS CLOSED on a non-numeric, zero, negative or fractional max steps", () => {
    for (const bad of ["abc", "0", "-1", "2.5", "3.0", "1e3"]) {
      expect(() => resolveLlmPolicy({ DF_LLM_MAX_STEPS: bad })).toThrow(EnvConfigError);
    }
  });

  it("rejects an out-of-range max steps", () => {
    expect(() => resolveLlmPolicy({ DF_LLM_MAX_STEPS: String(MAX_POLICY_STEPS + 1) })).toThrow(
      EnvConfigError,
    );
  });

  it("carries an optional model override", () => {
    expect(resolveLlmPolicy({ DF_LLM_MODEL: "deepseek/deepseek-chat" }).model).toBe(
      "deepseek/deepseek-chat",
    );
  });

  it("is case- and whitespace-insensitive for the level", () => {
    expect(resolveLlmPolicy({ DF_LLM_THINKING_LEVEL: "  HIGH  " }).thinkingLevel).toBe("high");
  });
});
```

## Task 2 — Provider adapter with graceful degradation

**Files:** Create `agent/lib/dark-factory/llm-policy-adapter.ts`; test
`tests/dark-factory/llm-policy-adapter.test.ts`.

**Objective:** map the canonical policy to OpenRouter request parameters, and
report honestly when a model cannot reason.

**RED cases:**
- `thinkingLevel: "off"` produces **no** reasoning parameter (not
  `effort: "off"`, which some providers reject).
- `"low" | "medium" | "high"` map to `reasoning: { effort: <level> }`.
- A model absent from the reasoning-capability table degrades: no reasoning
  parameter, and the result reports `applied: false` with a reason.
- The adapter **never** sends both `effort` and `max_tokens` — OpenRouter
  rejects that combination with HTTP 400 (already documented in
  `scripts/pr-reviewer.ts:428`).
- The adapter returns a provider-neutral result shape, so a future provider is a
  new adapter and not a change to `LlmPolicy`.

```ts
export interface AppliedPolicy {
  model?: string;
  reasoning?: { effort: ThinkingLevel };
  applied: boolean;
  /** Why the thinking level was not applied, when it was not. */
  reason?: string;
}
export function applyThinkingPolicy(model: string, policy: LlmPolicy): AppliedPolicy;
```

**Commit** `feat(df): LLM policy provider adapter with graceful degradation`.

## Task 3 — Apply the policy to the PR review path

**Files:** Create `scripts/pr-reviewer-policy.ts`; modify
`scripts/pr-reviewer.ts`; test `tests/pr-reviewer-policy.test.ts`.

**Objective:** the review request body derives its model and reasoning parameters
from the policy, while `PR_REVIEW_MODEL` remains an explicit override.

**RED cases:**
- With no policy configured, the review body is **unchanged** from today
  (`PR_REVIEW_MODEL` / `PR_REVIEW_REASONING_MAX_TOKENS` behaviour preserved).
- With `DF_LLM_THINKING_LEVEL=off`, the body carries no `reasoning` key.
- With a level set and a reasoning-capable model, the body carries
  `reasoning: { effort }` and never `effort` + `max_tokens` together.
- A malformed policy surfaces the config error rather than silently reviewing
  with defaults.

**Commit** `feat(df): apply LLM policy to the PR review path`.

## Task 6 — Orchestrator conversion (absorbs #217)

**Files:** Create `agent/orchestrator-model.ts`; modify `agent/agent.ts`; test
`tests/orchestrator-model.test.ts`.

**Objective:** convert the orchestrator to `defineDynamic` so the policy can be
applied per step **and** the cost gate (#217) can refuse a call before it starts.

**Critical property:** when neither a policy nor a cost gate is configured,
`buildOrchestratorModel()` returns the **static** model — identical to today.

**RED cases:**
- Unconfigured -> returns the static model, and `defineDynamic` is not involved.
- Policy configured -> returns a dynamic resolver.
- The resolver throws a config error on a malformed policy rather than falling
  back silently.
- With the cost gate configured and refusing, the step fails **before** any
  provider call is made.

**Risk — flagged:** this is the only task whose behaviour I cannot exercise
locally. `defineDynamic` needs the Eve runtime and Node >= 24. It is deliberately
last, so everything else can be reviewed and merged independently, and so this
step gets its own verification on your machine.

**Commit** `feat(df): policy-shaped and cost-gated orchestrator model`.
