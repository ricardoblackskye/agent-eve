# Establish the ADR practice and seed the first decisions (#237)

**Branch:** `docs/adr-foundation-237` (off `origin/main`)
**Advances:** #237 (ADR portion only — glossary and invariants remain in #237)
**Epic:** #232 — Documentation enhancement

## Goal

Start the Architecture Decision Record practice, so the *why* behind this system
stops living only in merged PR descriptions and issue threads. Deliver the
convention (template + index), the first seeded decisions, and a structural guard
that keeps the set honest from day one.

## Why now

The reasoning is not missing — it is buried. Recent examples, all correct, all
invisible to the next developer:

- why tenant attribution is write-once (`ON CONFLICT` deliberately omits
  `tenant_id`);
- why R1 records and reports while R2 refuses;
- why an unmeasured value renders as an em dash and never `0`;
- why story publish is fail-closed behind `STORY_ALLOWED_REPOS`.

Each of these took a decision to make and would take far longer to re-derive.
They are recorded nowhere durable: not linked from the code, not indexed, not
read by the next person.

## Intended fix

1. `docs/adr/README.md` — the index, plus the convention in one page: location,
   numbering, format, and the immutability rule.
2. `docs/adr/template.md` — the skeleton to copy.
3. The seeded ADRs below, one decision per file.
4. `tests/adr-integrity.test.ts` — the structural guard (see TDD below).
5. `ARCHITECTURE.md` (or the docs index, per #234) links to `docs/adr/`.

## The decisions to seed

| # | ADR | The decision, in one line |
|---|-----|---------------------------|
| 0001 | `tenant-attribution-is-write-once` | Resolve tenant at run acceptance and persist it immutably; never re-derive from today's repo mapping |
| 0002 | `r1-records-r2-refuses` | R1 records and reports usage; refusing runs arrives in R2, because refusing earlier would break operator work before the seed is everywhere |
| 0003 | `unmeasured-is-never-zero` | An absent measurement is an em dash, never `0`; `unmeasured = total − observed` |
| 0004 | `story-publish-is-fail-closed` | Refuse story creation unless `STORY_ALLOWED_REPOS` is set |
| 0005 | `sqlite-is-local-only` | SQLite is rejected when `NODE_ENV=production` or stage is preview/production; production needs a real adapter |
| 0006 | `provider-neutral-seams` | Canonical payload + adapter interface; no vendor SDK in core; the named vendor is swappable by config |
| 0007 | `control-state-is-db-backed-and-fail-closed` | `DF_CONTROL_DRIVER` selects console/sqlite/postgres; an unset or invalid driver fails closed |
| 0008 | `tenant-registry-is-ours-crm-is-bought` | Build the tenant registry; buy the CRM; build the one-way seam thin and later (#222) |

## TDD

An ADR is prose, so there is no runtime behaviour to drive. The RED anchor is a
**structural guard on the ADR set**, the same category as the repo's existing
doc-consistency test (`tests/env-example-coverage.test.ts`).

**RED** — `tests/adr-integrity.test.ts` asserting:
- every `docs/adr/NNNN-*.md` file is linked from `docs/adr/README.md`
  (no orphan ADRs — the rule written into the ADR convention);
- filenames match `NNNN-slug.md` with unique, sequential, zero-padded numbers;
- each ADR has a title, a date, a status, and the three required sections
  (Context, Decision, Consequences);
- an accepted ADR is never edited: `Superseded by NNNN` is the only permitted way
  to change one.

Run it: every assertion must fail because the files do not exist yet — not
because the test cannot find the directory.

**GREEN** — add the template, the index, and the eight ADRs.

**REFACTOR** — keep each ADR to roughly half a page; if one needs more, it is
probably two decisions.

## Risks / open questions

- **Scope creep into #237.** This branch delivers the ADR portion only. Glossary
  and invariants stay in #237; the PR must say *advances*, not *closes*.
- **Retrospective fidelity.** These ADRs are reconstructions from the record. If
  a remembered rationale is wrong or incomplete, that is worth correcting at
  GATE 1 rather than shipping a confidently-worded wrong history — a wrong ADR is
  worse than none, because it is authoritative-looking.
- **Which decisions qualify.** The eight above pass the trigger test ("would a
  developer ask *why is it like this*?"). The two candidates may not, and cutting
  them is a fine outcome.
- **Duplication with #234/#237.** When the docs site lands, ADRs should render as
  pages rather than being duplicated as prose. Link, do not copy.
- **cspell.** Eight new prose files is a lot of new vocabulary for one PR.
