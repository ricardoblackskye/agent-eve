# Story #136 — Tester Agent (Eve's Team) Implementation Plan

> **For Hermes:** Use test-driven-development to implement this plan task-by-task.
> **Branch:** `feat/tester-agent-136` (off `origin/main` = current)
> **Issue:** #136 (child of #132 epic)
> **Date:** 2026-09-16

**Goal:** Build the Tester Agent as a pre-PR validation gate that runs static analysis, smoke tests, and security scans to catch quality and security regressions before merge.

**Architecture:** A seam (`TesterAgent`) with a `ValidationRequest` canonical payload and `ValidationReport` output. Integrates with CI commands (`tsc`, `cspell`, `vitest`, security scan) running locally or via provider.

**Tech stack:** TypeScript, Vitest, existing linting infrastructure (cspell, tsc).

---

## Acceptance Criteria (from #136)

| AC | Description |
|----|-------------|
| AC1 | Given a developed branch with test outputs, when validation runs, it invokes run_static_analysis, execute_smoke_tests, run_security_scan |
| AC2 | The combined pass/fail result is reported |
| AC3 | If any check detects regression, branch is flagged as failed and PR blocked |
| AC4 | Validation runs before PR submission |

---

## Dependencies

- **R1 seams:** `StateStore` (read branch state, commit hash)
- **R2 seams:** `WorkerProvider` (can reuse for isolated check if needed)
- **Environment:** CI commands must be available (`npx tsc`, `cspell`, `vitest`)

## TDD Tasks

### Task 136.1 — Validation types + ValidationRequest payload

**Test target:** `tests/dark-factory/tester-agent.test.ts`

**RED:**
```typescript
toValidationRequest({branch, targetSha}) produces valid payload
→ reject missing branch
→ reject malformed SHA
```

**GREEN:**
```typescript
interface ValidationRequest { branch: string, targetSha?: string, env?: Record<string, string> }
interface ValidationReport { staticAnalysis: PassFail, smokeTests: PassFail, securityScan: PassFail, overall: 'pass'|'fail' }
toValidationRequest(data): ValidationRequest | throws ValidationError
```

### Task 136.2 — Static analysis runner (AC1: run_static_analysis)

**RED:**
```typescript
runStaticAnalysis(branch) → {ok: boolean, errors: string[]}
→ runs `npx tsc --noEmit` 
→ runs `npx cspell` on changed files
→ returns fail if any error
```

**GREEN:**
```typescript
async function runStaticAnalysis(): Promise<CheckResult>
// Execute commands, parse output, normalize to PassFail
```

### Task 136.3 — Smoke tests runner (AC1: execute_smoke_tests)

**RED:**
```typescript
runSmokeTests(branch) → {ok: boolean, passed: number, failed: number}
→ runs `npx vitest run`  
→ captures exit code + output count
→ returns fail on non-zero exit
```

**GREEN:**
```typescript
async function runSmokeTests(): Promise<TestResult>
```

### Task 136.4 — Security scan runner (AC1: run_security_scan)

**RED:**
```typescript
runSecurityScan(branch) → {ok: boolean, alerts: SecurityAlert[]}
→ runs security linter/tool if configured
→ returns pass if no alerts
→ returns fail if critical alerts
```

**GREEN:**
```typescript
async function runSecurityScan(): Promise<SecurityResult>
```

### Task 136.5 — Integration: runValidation loop

**RED:**
```typescript
runValidation(request) → ValidationReport
→ runs all three checks in parallel (or sequence for isolation)
→ aggregates results
→ emits metrics to MetricsStore (R1)
```

**GREEN:**
```typescript
async function runValidation(req: ValidationRequest): Promise<ValidationReport>
// compose all runners, handle timeouts, aggregate
```

### Task 136.6 — Blocking behavior (AC3: PR blocking)

**RED:**
```typescript

→ returns true if any check is fail
→ structured error message with details
```

**GREEN:**

```typescript
function shouldBlockPR(report: ValidationReport): report is ValidationReport & {blocking: true}
```
