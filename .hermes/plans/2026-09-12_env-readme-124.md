## Intended fix

### A. `.env.example`
Add the 11 missing user-settable vars under the existing grouped sections, each with a
non-empty descriptive comment. Classify each as **secret** (mask in Vercel) or **config**
(non-sensitive):

- **GitHub integration** section:
  - `GH_STORY_TOKEN` (secret) — token the Product Owner uses to create `[Story]` issues;
    read before `GH_RELEASE_TOKEN`/`GITHUB_TOKEN`. Needs `issues: write`.
  - `GITHUB_TOKEN` (secret) — final fallback token.
  - `GITHUB_REPO_OWNER` (config) — optional env override for the default publish owner.
  - `GITHUB_REPO_NAME` (config) — optional env override for the default publish repo.
  - `STORY_ALLOWED_REPOS` (config) — **mandatory fail-closed comma-separated allow-list**
    of `owner/repo` targets for story publishing. If unset, publishing is refused.
- **Agent runtime** section:
  - `NEXT_PUBLIC_EVE_API_KEY` (secret) — client-side Eve API key.
  - `MODEL_NAME` (config) — sprint-reporter model id (default `deepseek/deepseek-v4-pro`).
- **Sprint Metrics Report** section (new, mirrors the README section):
  - `GH_SPRINT_TOKEN` (secret) — `read:project` scope for board reads.
  - `SPRINT_PROJECT_OWNER` (config) — board owner override.
  - `SPRINT_PROJECT_NUMBER` (config) — board number override.
- **Vercel** section (new):
  - `VERCEL_PROTECTION_BYPASS` (secret) — bypass header for proxied/preview deploys.

Keep existing entries byte-identical (no churn). Group by concern per the issue's SHOULD.

### B. `README.md`
1. Add the four required explicit sections (issue AC):
   - **Vercel deployment settings** — project settings, required env vars in the dashboard,
     CLI commands (expand the existing "### Vercel" subsection into a clear checklist,
     noting which vars are **Sensitive** vs **plain config**).
   - **Git configuration steps** — clone, branch ruleset note, how repo→webhook mapping works
     (`release-manager.config.json`), and that `STORY_ALLOWED_REPOS` must list every repo the
     agent may publish to.
   - **Webhook setup instructions** — already partially present; promote to a clearly labelled
     subsection and add the `needs-story` / `generate-sprint-report` labels + `GH_WEBHOOK_SECRET`.
   - **Secrets / tokens management** — a consolidated table marking each var Sensitive (masked)
     vs plain config, and the rule "redeploy after changing any env var".
2. Reconcile the env tables with the final `.env.example` set (no phantom vars like the issue's
   example `VERCEL_TOKEN`/`GIT_REPO_URL`/`WEBHOOK_SECRET` — use the REAL names in the code).
3. Fix the stale model line ("default model is `gpt-4o`") to match `deepseek/deepseek-v4-pro`
   already referenced elsewhere in the README.

### C. Doc-consistency test (the RED anchor)
Add `tests/env-example-coverage.test.ts` that:
- Reads `.env.example`, extracts every `KEY=` / `# KEY` reference.
- Greps non-test source files for `process.env.<NAME>`.
- Asserts every user-settable `<NAME>` appears in `.env.example`.
- This is the regression guard so the gap cannot re-open silently.

## Risks / open questions

- **Test-only vars** (`BASE_URL`, `CI`, `PLAYWRIGHT_EXECUTABLE_PATH`): intentionally excluded
  from `.env.example` (they are CI/Playwright runtime knobs, not app boot config). The test
  will whitelist these so it does not force them into `.env.example`.
- **Vercel-auto vars** (`VERCEL_ENV`, `VERCEL_GIT_REPO_OWNER`, `VERCEL_GIT_REPO_SLUG`):
  auto-injected by Vercel; documented as "auto-provided, do not set manually" rather than given
  a placeholder line.
- **No real secrets committed** — all placeholders, matching the issue's security constraint.
- The README example in #124 lists `VERCEL_TOKEN` / `GIT_REPO_URL` / `WEBHOOK_SECRET` as
  *illustrative* — those are NOT real vars in this repo. Use the real names from code, not the
  issue's hypothetical examples.
