# Security hardening: open redirect, timing attack, unsafe file reads

## Goal

Close three security findings on `main` in one branch and PR:

- #571 (critical) open redirect via `decision.redirectTo` in the dev and Google auth
  callback routes.
- #572 (high) non-timing-safe bearer-token comparison in `agent/channels/eve.ts`.
- #573 (high, triaged to medium) path-traversal in file reads driven by untrusted
  run/story config.

## Root cause (verified against origin/main)

- #571: both `app/api/auth/dev/route.ts` and `app/api/auth/google/callback/route.ts`
  build the redirect as `new URL(decision.redirectTo, resolveRequestOrigin(request))`.
  `resolveRequestOrigin` validates the *authority* it puts in the `Location`, but
  `redirectTo` is never origin-checked. An absolute `redirectTo` (`https://evil.com`)
  makes `new URL` ignore the base and emit an off-origin `Location` - a classic open
  redirect usable for phishing and credential theft.
- #572: `agent/channels/eve.ts:33` does `if (token === expectedKey)`. A plain `===`
  on a secret is not constant-time; response-time differences leak the key byte by byte.
- #573: reads such as `agent/lib/dark-factory/local-run-checkout.ts:84` build paths
  from a run/story-supplied directory. Most of the 17 cited sites are code-supplied
  (fixed config paths, fixed filenames, single `readdir` names) and are low risk;
  `self-improve.ts:360` is already contained via `path.relative`. The genuine exposure
  is reads reachable from untrusted config, where a malicious repo path could read
  outside the workspace. No shared containment helper exists.

## Intended fix

- #571: extract `safeRedirect(request, redirectTo): string`. Build the URL, then if
  `built.origin !== resolveRequestOrigin(request)` return `new URL("/", resolveRequestOrigin(request)).toString()`.
  Use it in both routes. Fail closed - never emit an off-origin `Location`.
- #572: extract `constantTimeEqual(a, b): boolean` (uses `node:crypto` `timingSafeEqual`
  after a length guard) into `agent/channels/auth.ts`; call it from `bearerAuth`.
- #573: add `safeReadWithin(root, target): string` (resolve both, require
  `path.relative(root, target)` is not `..` and not absolute) in
  `agent/lib/dark-factory/fs-safe.ts`; apply it to the untrusted-input reads
  (`local-run-checkout.ts`, and any other read whose path derives from run/story
  config). Leave code-supplied reads untouched.

## Risks and open questions

- #571: confirm legitimate relative redirects (for example `/dashboard`) still resolve
  after the guard - covered by the relative test case.
- #572: `timingSafeEqual` throws on unequal buffer lengths, so the length guard must
  precede it - covered by the length-mismatch test.
- #573: keep severity honest - most of the 17 sites are internal, so only harden the
  untrusted-input reads and recommend downgrading high to medium. Do not churn 17 files.
- ADR: a fail-closed redirect-validation posture is a deliberate security decision and
  warrants an ADR.

## Settled decisions

- One branch and one PR closing #571 #572 #573 (the user grouped them as "3 security
  issues").
- Fail-closed defaults for both the redirect guard and the file-read guard.
- Severity on #573: recommend downgrade high to medium given the triage.
