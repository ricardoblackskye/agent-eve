**Goal:** One integration test that proves the Dark Factory pipeline end-to-end —

**Issue:** #269 · **Epic:** #267 (P0) · **Branch:** `feat/df-pipeline-e2e-269`

**Tech stack:** TypeScript, Vitest, `node:sqlite` (`:memory:`) for the state/run-history seams.

## Scope decision (agreed at review)

The issue AC includes *"issue labelled `df:done`/`df:failed`"*, but **the library never
applies the terminal labels** — `TRIGGER_LABELS.done`/`.failed` appear only in the trigger
*guard* and its test; `df:done` is applied solely by `scripts/dark-factory-runner.ts`, and
`df:failed` is applied **nowhere**. So #269 is scoped to prove the pipeline **up to
"PR opened (not merged)"**; the terminal-label wiring is filed separately as **#284**
(sub-issue of #267).

**Consequence:** #269 is a **test-only** deliverable — it composes existing, already-tested
pieces; it introduces no production module. (If composing surfaces a genuine wiring gap,
that gap becomes a minimal fix in this PR and is called out in the PR body.)

## What the pipeline actually is (as built)

```text
GitHub webhook  ──►  decideDarkFactoryTrigger()        (trigger.ts — pure decision)
                       │  kind: "trigger" | "not-a-trigger" | "refused" | "abort" | "resume"
                       ▼
                 runDarkFactoryDispatch()              (entry.ts)
                       │  acceptDelivery → run bound ; + df:running ; POST /eve/v1/session
                       ▼   (out of band — the webhook never runs the loop)
                 Dispatcher.dispatch()                 (dispatch.ts — at-most-once, retry, park)
                       ▼
                 createDispatchHandler({ stages })     (dispatch-handler.ts — #268)
                       │  developer → tester → pr  (checkpoint before each)
                       ▼
                 PR OPENED — terminal automated action, NEVER merged
```

Entry: `app/api/github/webhook/route.ts` (composition of trigger → entry). The worker is
never invoked in-request.

## Approach — one composed integration test, all real seams, no network

New file `tests/dark-factory/dark-factory-pipeline-e2e.test.ts`. Everything runs against
**real** modules with the external edges mocked exactly as the repo already does:

| Edge                | Real module                                                           | Mocked as                                                 |
|---------------------|-----------------------------------------------------------------------|-----------------------------------------------------------|
| GitHub labels       | `entry.ts` `LabelWriter`                                              | recording `add`/`remove` (records `+df:running`, `-…`)    |
| Session handoff     | `entry.ts` `postSession`                                              | `recordingPost()` (asserts one POST to `/eve/v1/session`) |
| Run history / state | `SqliteRunHistoryStore(":memory:")`, `SqliteStateAdapter(":memory:")` | real, in-memory                                           |
| LLM (developer)     | `runMultiFileCodingLoop` worker                                       | stub worker writing files into a `mkdtemp`                |
| Tester checks       | `createTesterAgent({}, { commandRunner })`                            | stub `CommandRunner` (pass/fail)                          |
| PR + comments       | `runDefinitionOfDone` deps                                            | Mock-GitHub opener/comment writer                         |

Reuse the proven helper idioms verbatim from `tests/dark-factory/entry.test.ts`
(`recordingPost`, `recordingLabels`, `ENV`, `triggerDecision`, `deps`) and
`dark-factory-e2e-integration.test.ts` (Architect → Validator → Developer → DoD composition).

The three `FactoryStages` (`#268`) are composed from the real agents:

```ts
const order: string[] = [];
const stages: FactoryStages = {
  developer: async (ctx) => { order.push("developer"); await runMultiFileCodingLoop({ plan, tools, worker }); },
  tester:    async () => { order.push("tester");    return { passed: (await testerAgent.runValidation(req)).overall === "pass" }; },
  pr:        async () => { order.push("pr");        await runDefinitionOfDone(dodDeps, dodTask); },
};
```

## Task structure (TDD)

### Task 0 — Branch & plan *(this step)* — then **GATE 1**

### Task 1 — RED: the end-to-end test (the primary `it`)
Create `tests/dark-factory/dark-factory-pipeline-e2e.test.ts` with ONE `it` that walks the
whole chain:
1. `decideDarkFactoryTrigger(labeled payload, ENV)` → `kind === "trigger"`.
2. `runDarkFactoryDispatch(decision, deps)` → `status === "dispatched"`; labels recorded
   `+df:running` exactly once; exactly one POST to `/eve/v1/session`; the run is queryable
   via `runHistory.getRun(runId)`.
3. `new Dispatcher({ store, handler: createDispatchHandler({ stages }), sleep }).dispatch(event)`
   → `status === "succeeded"`; `order === ["developer","tester","pr"]`.
4. The Mock-GitHub opener recorded **exactly one** `createPullRequest`.

**Run:** `npx vitest run tests/dark-factory/dark-factory-pipeline-e2e.test.ts`
**Expected:** FAIL for the right reason. If the composition is already complete the
assertions may pass first time — that is the integration-test case, and **Task 2 is then
mandatory** to prove the test is not vacuous.

### Task 2 — MANDATORY: prove the test can fail (non-vacuity)
Temporarily mutate the pipeline and confirm the assertion catches it, then revert:
- reorder stages (`["developer","pr","tester"]`) → the `order` assertion fails;
- make the tester return `{passed:true}` unconditionally on a failing runner → the gate
  assertion fails;
- point the opener at a `/merge` URL → the never-merged assertion fails.
Record the mutation results in the PR body (mirrors the repo's `mutation: … is caught` guard style).

### Task 3 — the terminal-label guard prevents a second run (AC2)
Add `it`s asserting:
- a payload whose issue `labels` already include `df:done` (and `df:failed`) →
  `decideDarkFactoryTrigger` returns `{ kind: "not-a-trigger" }`, so
  `runDarkFactoryDispatch` returns `ignored` and performs **no** label write / handoff / run;
- re-delivering the SAME `deliveryId` → entry returns `held` (`duplicate`) and the handler
  is not invoked a second time (assert the stage recorder did not grow).

### Task 4 — PR is opened, never merged (AC3)
Assert the Mock-GitHub recorded the PR creation and **no** merge/label-of-merge call; and
that `GitHubPrWriter` exposes no merge verb (`(writer as any).merge === undefined`) — a
direct assertion of the `pr-writer.ts` invariant ("merging is STRICTLY forbidden").

### Task 5 — Local gate (MANDATORY before any push)
```bash
npx vitest run tests/dark-factory/dark-factory-pipeline-e2e.test.ts
npx vitest run tests/dark-factory
npx vitest run                          # full suite, no NEW regressions
npx tsc --noEmit --incremental false
npx -y cspell@8 --config .cspell.json tests/dark-factory/dark-factory-pipeline-e2e.test.ts
npx vitest run tests/doc-drift-guards.test.ts tests/env-example-coverage.test.ts
DF_PLATFORM_PROVIDER=generic npm run build
```

## Risks & open questions
1. **Test-only release.** #269 adds no production code, so the usual "no production code
   without a failing test" is trivially met; the anti-vacuity mutation (Task 2) is what
   gives the test teeth. **Confirm** that is acceptable, vs. wanting a thin reusable
   `runFactoryPipeline()` helper extracted (YAGNI — the existing e2e test composes inline).
2. **No ADR.** A test-only change makes no architectural decision; the terminal-label
   deferral is recorded on **#284**. **Confirm** no ADR is expected for this issue.
3. **"One integration test"** is read as one `it` for the full chain plus focused `it`s for
   the guard and never-merged. If a single monolithic `it` is preferred instead, say so.
4. If composing reveals the entry→dispatcher link needs a small production glue function,
   that will be added here and flagged — currently believed unnecessary.
