# Dark Factory Progress Board (UI) Implementation Plan — issue #200

> **For Hermes:** Implement with strict RED→GREEN→REFACTOR TDD, one behavior at a
> time. Do not start implementation until the user approves this plan.

**Goal:** Add an authenticated Dark Factory progress board — an Overview
(Factory status), a filterable Execution ledger (run table), and a Run detail
view — that consumes the provider-neutral read API from #199, with component
tests for the empty / loading / error / active / blocked / terminal states.

**Architecture:** Next.js 16 App Router pages under `app/dark-factory/`, client
components that poll `/api/dark-factory/*` on an interval (no new runtime
dependency), and a pure view-model module that maps API payloads to UI state and
that is unit-tested in the `node` environment. Rendering is tested with Testing
Library under `jsdom`. Styling follows the repo's plain-CSS `app/globals.css`
(dark theme), building on the agreed operator-split mockup.

**Tech Stack:** TypeScript, Next.js 16 App Router (client components), React 19,
plain CSS, Vitest + `jsdom` + `@testing-library/react`.

2. **Component-test stack:** add `jsdom` + `@testing-library/react` devDeps and

## API → UI mapping (explicit, honest)

| UI surface                                  | Source                  | Rule                                                                                                                       |
|---------------------------------------------|-------------------------|----------------------------------------------------------------------------------------------------------------------------|
| ACTIVE / BLOCKED / COMPLETED / FAILED tiles | `metrics.statusCounts`  | ACTIVE = queued + running; BLOCKED = blocked; COMPLETED = succeeded; FAILED = failed + aborted                             |
| Outcome mix                                 | `metrics.statusCounts`  | same four categories; percentages from the summed total                                                                    |
| Outcome trend chart                         | `metrics.trend`         | one point per `{ date, count }` (daily terminal outcomes)                                                                  |
| Resource snapshot                           | `metrics.measured`      | mean latency = `latencyMs.sum / latencyMs.count`, total cost = `costUsd.sum`; "unmeasured" = total runs − `measured.count` |
| Recent executions + run table               | `/runs`                 | one row per `RunSummary`                                                                                                   |
| Run detail summary tiles                    | `/runs/[runId]` summary | `startedAt`, elapsed = `completedAt − startedAt`, `attemptCount`, `reviewCount`, `costUsd`                                 |
| Event timeline                              | `/runs/[runId]` events  | ordered by `sequence`; label from `type`, description from `stage`/`status`                                                |
| Worker checkpoints                          | `/runs/[runId]` events  | grouped by `stage` (dispatch/review/terminal); unknown stages shown raw                                                    |
| Measured metrics (detail)                   | summary + events        | `latencyMs`, `iterationCount`, `fixCycleCount`, `findingCount`, `resolvedCount`, `acceptedCount`                           |

**Honesty rules (must hold in tests):** an absent measurement renders `—`, never
`0`; a missing count is derived only as `total − observed`, never invented; an
unrecognized event `type` is displayed literally rather than guessed.

### Task 1: Pure formatting helpers

**Files:** `app/dark-factory/ui/format.ts`, `tests/dark-factory-ui/format.test.ts`.

TDD one behavior per cycle (RED first each time):

- `formatRelativeTime(iso, now)` → `"now"`, `"2m"`, `"3h"`, `"1d"`.
- `formatDuration(fromIso, toIso)` → `"14m 02s"`; returns `"—"` when either is absent.
- `formatCostUsd(usd)` → `"$0.42"`; returns `"—"` when `undefined` (never `"$0.00"`).
- `formatCount(n)` → `"07"` zero-padded to two digits.

Run after each RED: `npx vitest run tests/dark-factory-ui/format.test.ts`.

### Task 2: Pure view-model derivations

**Files:** `app/dark-factory/ui/view-model.ts`, `tests/dark-factory-ui/view-model.test.ts`.

Behaviors (each its own RED→GREEN cycle):

- `categorizeStatus(status)` → `"active" | "blocked" | "completed" | "failed"`.
- `toKpiTiles(statusCounts)` → the four categories with summed counts and a
  `label`/`hint` (e.g. `{ key:"active", value:7, hint:"running now" }`).
- `toOutcomeMix(statusCounts)` → `{ segments: [{ key, count, percent }], total }`
  with percentages that sum to 100 for a non-empty total.
- `toResourceSnapshot(metrics)` → `{ meanLatencyMs?, totalCostUsd?, unmeasured }`
  where `unmeasured = totalRuns − measured.count`; absent measurements are
  `undefined` (asserted), never `0`.
- `toTableRows(runs, now)` → `{ runId, issue, repo, status, stage, updatedLabel,
attempts, elapsedLabel, costLabel }`.
- `toDetailView({ summary, events })` → summary tiles, ordered timeline entries,
  worker checkpoints grouped by stage, and measured metrics — with unknown event
  types preserved literally.
- `toQueryParams(filters)` → `URLSearchParams` for the read API (`statuses`,
  `repo`, `issue`, `from`, `to`, `limit`), omitting empty filters.

Run: `npx vitest run tests/dark-factory-ui/view-model.test.ts`.

### Task 3: Polling data hook

**Files:** `app/dark-factory/ui/use-run-query.ts`, `tests/dark-factory-ui/use-run-query.test.tsx`.

## Risks / open questions

- **Global `include` change** may collect stray `.tsx` files: mitigated by
  keeping board tests under `tests/dark-factory-ui/` and using the explicit
  `// @vitest-environment jsdom` docblock.
- **Timer leaks in polling tests**: use `vi.useFakeTimers()` + unmount in
  `afterEach`; assert no post-unmount `setState`.
- **`next/link` in `jsdom`**: keep leaf components on plain `<a>`; only the
  layout/pages use `next/link`, so unit tests avoid the Next runtime.
- **Honest metrics**: the API exposes only latency/cost sums with counts, so the
  UI shows mean latency and total cost and an "unmeasured" count — it never
  fabricates a median or a zero.
- **Out of scope (YAGNI):** realtime streaming, CSV export, settings, and any
  write path; the board is read-only.
