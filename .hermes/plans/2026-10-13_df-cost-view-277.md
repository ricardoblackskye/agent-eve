# Plan — #277: the operator cost view (prove what ships, complete the data, add the charts)

**Branch:** `feat/df-cost-view-277`
**Issue:** [#277](https://github.com/ricardoblackskye/agent-eve/issues/277) (sub-issue of #267)

## Current state (verified, not assumed)

The original one-line body asked to "surface `cost-budget-query`/`tenant-budget-query` in an operator
view". That already ships:

- `app/dark-factory/page.tsx:126` — `<CostBudgetsPanel/>`: one row per canonical category,
  **Category / Spent / Reserved / Remaining / Calls / Total**, with an explicit gap row for a category
  that has no budget.
- same page `:143–144` — _"Customer usage"_ + _"Customer budgets"_.
- `UsagePanel` already tables **totals + by model + by day + by run**.
- all four query modules are implemented and tested.

Charts are **not** new here either: `components.tsx` ships `TrendChart` (inline-SVG line chart),
`OutcomeMix`, `KpiTiles`, `MetricTile`. No chart library exists and none is needed.

## The real gaps

1. **`CostBudgetsPanel` has no test at all.** Every other panel is covered. The operator cost view is the
   one thing shipping unproven.
2. **Collected data that never reaches the UI.** The usage row carries `tokensIn`, `tokensOut`,
   `durationMs`, `taskType`, `pbiId`, `model`, `tenantId`; the panels surface only Calls + Cost per
   model — no **tokens**, no **duration**, no **per-task-type** breakdown.
3. **The operator's question is unanswered:** _"will we exceed the cap this month?"_ Cap, spent and
   reserved are on screen, but nothing relates them to the period.

## Tasks (RED → GREEN)

**T1 (RED) — prove the shipped view.** A dedicated `CostBudgetsPanel` test: one row per canonical
category with cap/spent/reserved/remaining; an explicit gap row for an unconfigured category;
`UNMEASURED` — never `$0.00` — when a figure is absent.
**Non-vacuity:** breaking the reserved/measured split, or rendering unmeasured as zero, must fail.

**T2 (RED) — surface the missing dimensions.** Per-model **tokens (in/out)** and **duration**
alongside cost; a **per-task-type** cost breakdown. The data already exists in the ledger; this is
presentation, not new collection.

**T3 (RED) — the charts, one question each.** Reuse the existing inline-SVG idiom; **no new
dependency**:

| chart              | answers                             | source (already available)              |
| ------------------ | ----------------------------------- | --------------------------------------- |
| daily cost trend   | are we spending faster than usual?  | the usage _by day_ series               |
| budget burn-down   | will we exceed the cap this period? | cap / spent / reserved + the period key |
| cost by model      | which model dominates spend?        | usage _by model_                        |
| cross-tenant spend | which customer is expensive?        | tenant usage query (operator only)      |

**Non-vacuity:** a **missing** day, model or tenant must render as absent — never plotted at zero.
A gap and a zero are different things, and a chart that conflates them invents spend that never
happened.

**T4 (GREEN)** — implement what T1–T3 expose. Extend `globals.css` and the CSS guards for anything new:
`style-contract.test.ts` requires a `globals.css` rule for every table class a component uses, and
`dashboard-css.test.ts` exists precisely because these panels once shipped with **no CSS** (#205).

**T5** — ADR only if the charts introduce a rule worth recording (candidate: _an unmeasured value is
absent, not zero, on a chart_ — extends ADR 0003 to the visual layer).

## Constraints to hold

- **Reserved ≠ spent.** The price table is a reservation CEILING (ADR 0027, #335); `Reserved` is a real
  distinct quantity that must not be blended into spend.
- **Unmeasured ≠ zero** (ADR 0003) — in tables and on charts.
- **Tenancy.** The run-metrics aggregate is operator-only and tenant scope is derived server-side,
  fail-closed (ADRs 0016/0017; proven in #329). No factory-wide aggregate for a customer.
- **Tailwind only** (ADR 0009); inline SVG for charts, as `TrendChart` already does.
- **Burn-down honesty:** the period-elapsed marker is wall-clock, not measured spend — it must be
  labelled as such rather than implying a projection we cannot compute.
