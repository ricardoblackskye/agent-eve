# Dark Factory R2 — Worker Environment + Credential Boundary (feat/df-worker-env)

> **For Hermes:** Use test-driven-development to implement this plan task-by-task.
> **Branch:** `feat/df-worker-env` (off `origin/main` = `7ca1a58`, the PR #147 merge commit)
> **Stories (R2 work items):** #142 (Credential ingress / worker privilege boundary) · #135 (Component B: Containerised Compute & Code Access)
> **Parent epics/tasks (IN SCOPE, both):** #130 (Component B — Epic) · #141 (Credential ingress — Task) → #128 → #127
> **Date:** 2026-09-15
> **Prerequisite:** R1 (`#134`/`#138`/`#140`) is merged and closed. This branch starts from its merge commit.

**Goal:** give the Dark Factory "real hands" — a worker sandbox Eve can push context into and execute
in, plus the credential boundary that lets that sandbox touch a repo **without ever holding a broad
PAT**. Builds directly on the R1 seams (`StateStore`, `Dispatcher`, `MetricsStore`); no R1 file needs
to change behaviour.

**Architecture (2-3 sentences):** two new seams under `agent/lib/dark-factory/`, same
canonical-payload + adapter + fail-closed-default pattern as R1. `credentials.ts` is a **broker**: it
holds the operator's existing token, issues the worker a short-lived *lease* (opaque handle + TTL +
repo allow-list), and adjudicates every access request — so the sandbox receives a lease, never the
PAT. `worker-env.ts` is a **provider seam**: `provision → pushContext → exec → destroy`, with a
selector for *where* the environment runs and a `local` default that is honestly reported as a
dry-run, not as isolated compute.

## Scope decisions (from the operator, this session)

1. **Order:** `#142` (credential boundary) **first**, then `#135` (worker environment). #135's AC5
   explicitly depends on the boundary, and #142 is pure policy code with no external credentials.
2. **Credential source:** **use the existing token for now** (refactorable later). Reconciled with
   #142's ACs by keeping the token **in the broker, not the sandbox**: the worker gets a lease; the
   broker performs the privileged operation. This satisfies "MUST NOT deliver a broad long-lived PAT
   to any worker sandbox" *structurally*, and gives real TTL/revocation/403 semantics without a GitHub
   App. Swapping the source to a GitHub App installation token later changes one adapter, not the seam.
3. **Worker environment:** provider **seam + `local`/dry-run default** that honestly reports it is not
   isolated. `e2b`/`modal` adapters are added when keys exist — no new runtime dependency in R2.

## Non-goals in R2 (explicit)

- No Developer/Tester *agents* (#133/#136 are R3) — R2 delivers the environment they will run in.
- No circuit breaker / cost guard (#144, R3).
- No live container isolation: without E2B/Modal keys, no R2 test may claim isolated compute.
- No queue (QStash) — still in-process and deterministic.
- No change to R1 behaviour; R2 only adds modules and wiring.

## Story #142 — Credential ingress / worker privilege boundary (`credentials.ts`)

**Intent (from #141/#142):** a worker needs repo-write for `git_clone`/result pushes, but must receive
a short-lived, repo-allowlisted credential per task rather than a broad PAT.

**ACs to anchor TDD on:**
- AC1: on dispatch, the worker receives a credential scoped to exactly the allowlisted repo(s), TTL ≤ 60 min.
- AC2: an operation outside the allowlisted repo(s) is rejected with **403** and no write occurs.
- AC3: on completion (or TTL expiry) the credential is revoked; further use returns **401**.
- AC4: a broad long-lived PAT in the environment MUST NOT be delivered to the worker sandbox.
- Constraints: MUST NOT deliver a broad PAT; reusable per task; refactorable credential source.

### TDD tasks (#142)

**Task 142-1 — canonical grant + lease shapes**
- Test target: `tests/dark-factory/credentials.test.ts`
- RED: `toRepoGrant({repos, ttlSeconds})` normalises to lowercase `owner/repo` entries, rejects an empty
  repo list and any TTL > 3600s (`InvalidGrantError`); `isExpired(lease, now)` is pure and clock-injected.
- GREEN: pure helpers + types.

**Task 142-2 — broker seam + fail-closed default**
- RED: the default broker **refuses to issue a lease** when no token is configured (explicit error, no
  lease object), and reports `mode: "blocked"` — mirroring `ConsoleStateProvider`. No side effects.
- GREEN: `CredentialBroker` interface (`issue`, `authorize`, `revoke`) + refusing default.

**Task 142-3 — lease issuance: the PAT never leaves the broker (AC1 + AC4)**
- RED: with a token in the env, `issue(grant)` returns `{ leaseId, expiresAt, repos }`; assert
  `JSON.stringify(lease)` does **not** contain the token, the lease is opaque, and the token is
  readable only inside the broker. Also: `authorize(lease, "ricardoblackskye/agent-eve")` → allowed.
- GREEN: mint an opaque lease id, store the mapping in the broker, keep the token private.

**Task 142-4 — allow-list enforcement → 403 (AC2)**
- RED: a grant for `ricardoblackskye/agent-eve`; `authorize(lease, "ricardoblackskye/other-repo")` →
  `{ status: 403 }` and **no write callback fires** (assert the injected writer was never called).
- GREEN: compare against the grant's normalised repo set; deny by default.

**Task 142-5 — TTL expiry and revocation → 401 (AC3)**
- RED: with an injected clock, advance past `expiresAt` → `authorize` returns `{ status: 401 }`;
  `revoke(lease)` → the very next `authorize` returns `{ status: 401 }`; a second `revoke` is a no-op
  (idempotent, mirroring the repo's 404-as-success label rule).
- GREEN: expiry check + a revoked set; revocation only needs to reach the broker, not GitHub.

**Task 142-6 — env wiring + test hook**
- RED: `createCredentialBroker(env)` → refusing default when no token; `mode: "live"` when one is set;
  reuses the SAME token resolution order as the rest of the app
  (`GH_STORY_TOKEN` → `GH_RELEASE_TOKEN` → `GITHUB_TOKEN`).
- GREEN: switch + reuse the existing resolution helper.

**Task 142-7 — HTTP adjudication endpoint (byte-exact 403/401)**
- RED: start the endpoint on an ephemeral loopback port and drive it with real `fetch`:
  `POST /authorize` with a valid lease for an allowlisted repo → **200**; for a non-allowlisted repo →
  **403**; with a revoked/expired/unknown lease → **401**; malformed body → **400**. Assert no response
  body or header ever contains the token, and that issuance is NOT reachable over HTTP.
- GREEN: framework-agnostic `(request) => { status, body }` handler + a `node:http` binding used by the
  tests; loopback-only by default.

## Story #135 — Worker environment (`worker-env.ts`)

**Intent (from #130/#135):** a sandboxed environment with a filesystem, Git and a requested runtime,
where Eve pushes the skeletal file map + PBI data and executes the worker's logic.

**ACs to anchor TDD on:**
- AC1: worker logic runs inside an isolated container with filesystem, Git and the requested runtime.
- AC2: pushed context (skeletal file map + PBI data) is present and readable before execution.
- AC3: the environment location is **selectable**, not hardcoded.
- AC4: on completion the container is torn down — nothing persists.
- AC5: the worker receives a short-lived, repo-allowlisted credential, per #142.

### TDD tasks (#135)

**Task 135-1 — canonical `WorkerTask` payload**
- Test target: `tests/dark-factory/worker-env.test.ts`
- RED: `toWorkerTask({taskId, repo, runtime, files, command})` keeps only canonical fields, rejects a
  missing `taskId`/`repo`/`command`, and rejects an unknown `runtime` (`node`/`python` only).
- GREEN: pure normaliser + validation.

**Task 135-2 — provider seam + local dry-run default (AC3)**
- RED: `createWorkerProvider(env)` returns the `local` provider by default and by
  `DF_WORKER_PROVIDER=local`; an unknown value throws (naming it), like `DF_STATE_DRIVER`; every result
  from the local provider reports `mode: "dry-run"` and `isolated: false` — it must never claim
  isolation it cannot provide.
- GREEN: interface (`provision`, `pushContext`, `exec`, `destroy`) + local adapter that records intent
  without executing untrusted code.

**Task 135-3 — context push before execution (AC2)**
- RED: `pushContext(handle, {fileMap, pbi})` writes through to the provider; calling `exec` before any
  push throws an explicit "context not pushed" error; after a push, `exec` sees the exact context.
- GREEN: track pushed context on the handle; order-enforce it.

**Task 135-4 — teardown is unconditional (AC4)**
- RED: `destroy` is called exactly once when exec **succeeds**, when exec **throws**, and when
  `pushContext` throws (assert via a recording fake provider) — nothing persists on any path.
- GREEN: `try/finally` lifecycle helper (`withWorker`), so callers cannot forget teardown.

**Task 135-5 — credential boundary integration (AC5)**
- RED: provisioning a task obtains a lease from the broker for the task's repo; the handle carries the
  **lease**, never the token; a task whose repo is not in the grant is refused before any provisioning
  with a 403-shaped result and no container is created.
- GREEN: compose broker + provider in `withWorker`; the worker callback receives `{leaseId, repos}` only.

**Task 135-6 — dispatch integration (wiring)**
- RED: a `Dispatcher` handler built from `withWorker` runs the full path — CI event → lease → provider →
  context push → exec → teardown — and emits a `worker-env` task metric through the R1 metrics seam.
- GREEN: a `createWorkerHandler({broker, provider, recorder})` factory in `index.ts`.

## Risks / open questions

1. **The credential boundary ships a real HTTP adjudication endpoint** (operator decision), so
   "rejected with HTTP 403" and "further use returns HTTP 401" are byte-exact over a socket rather
   than a status carried in a return value. **Issuance stays in-process** — a worker must never be
   able to mint its own lease — so only adjudication is exposed, bound to loopback for R2. The handler
   is framework-agnostic (request → status/body) so R3 can mount it as a Next route when a remote
   E2B/Modal sandbox needs an out-of-process worker to call back into the orchestrator.
2. **The existing PAT is broad** and now sits behind the broker. That satisfies AC4 structurally, but
   the operator should still treat it as a deployment secret; switching the *source* to a GitHub App
   installation token later is one adapter. Note GitHub cannot revoke an installation token early, so
   the broker remains the thing that makes early revocation real — another reason to keep it.
3. **No live isolation is proven in R2** (no E2B/Modal key, Docker availability on this host unknown).
   The plan therefore ships `isolated: false` for the default provider; claiming otherwise would be a
   fabricated capability.
4. **`DF_WORKER_ALLOWED_REPOS` vs `STORY_ALLOWED_REPOS`** — a separate allow-list keeps the two
   blast radii independent, but if the operator prefers one list, say so before the docs commit.
5. **Node/evals:** local `npm run dev`/`eve` still needs Node 24 (host has 22); CI remains the eval gate.

Operator decisions already taken: order = #142 then #135; credential source = existing token, held by
the broker; environment = provider seam with an honest `local` dry-run default.
