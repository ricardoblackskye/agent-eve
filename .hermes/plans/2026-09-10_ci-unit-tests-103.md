# Plan: Add unit test execution to the CI pipeline (#103)

- **Date:** 2026-09-10
- **Branch:** `feat/ci-unit-tests-103`
- **Issue:** #103

## Goal

Run the Vitest unit test suite (`tests/*.test.ts`, currently 145 tests) automatically
on every pull request targeting `main` and every push to `main`, reported as a PR
status check, failing the run (non-zero exit) when any test fails.

## Root cause (verified)

- `package.json` lists `vitest` as a devDependency but has **no `test` script** —
  the suite is only runnable via `npx vitest run`.
- `.github/workflows/ci.yml` has jobs `typecheck`, `build`, `evals`, `e2e`,
  `megalinter`, `production-evals` — but **no job that runs vitest**. The unit
  suite is therefore local-only and never enforced in CI (the "evals" the user sees
  are the Eve eval framework, a different thing).

## Intended fix

1. Add `"test": "vitest run"` to `package.json` `scripts` (the canonical local
   invocation — the issue's "no change to how tests are invoked locally" constraint).
2. Add a `test` job to `.github/workflows/ci.yml`:
   - Node 24 (`${{ env.NODE_VERSION }}`), `npm ci`, then `npm test`.
   - **No secrets** — the suite is hermetic (all `fetch` calls and env vars are
     mocked/stubbed inside the tests).
   - Runs in parallel with `typecheck`/`build` (independent; keeps latency low).

## Tasks (TDD, config-change pattern)

1. **RED** — `tests/ci-unit-tests.test.ts`: assert (a) `package.json` `scripts.test`
   is `"vitest run"`, and (b) `ci.yml` declares a `test` job running `npm ci` and
   `npm test`. Follow the existing `tests/preview-evals-workflow.test.ts` pattern
   (`readFileSync` + string/regex match; no YAML parser is a project dependency).
2. **GREEN** — add the `test` script and the `test` job.
3. **Verify** — `npm test` passes (hermetic, no secrets), full suite green, cspell +
   prettier clean.

## Files likely to change

- `package.json` — add `test` script.
- `.github/workflows/ci.yml` — add `test` job.
- `tests/ci-unit-tests.test.ts` — new config test.

## Validation

- `npm test` → 145 tests pass.
- Full suite (including the new config test) green.
- Manual (post-merge): a PR shows a "Unit Tests" status check that passes; a
  deliberately failing assertion fails the job with the failing test name visible.

## Risks / open questions (out of code scope — flag for the user)

- **"MUST NOT allow merging without the check passing"** requires a GitHub
  **branch-protection rule** requiring the "Unit Tests" status check on `main`.
  This is a repo *settings* change (GitHub UI or REST API), not part of the code PR.
- **"SHOULD NOT deploy/release if unit tests fail"** — Vercel deploys independently
  of GitHub Actions; gating deploy on the test check needs Vercel's
  "GitHub Checks" deployment protection (Vercel project settings), also out of
  code scope.
- **Latency < 10 min** — the suite runs in ~4s locally; `npm ci` dominates. Node 24
  is already the CI version. No concern expected, but the first CI run will confirm.
