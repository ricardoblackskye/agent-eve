# Story #133 — Developer Agent (Eve's Team) Implementation Plan

> **For Hermes:** Use test-driven-development to implement this plan task-by-task.
> **Branch:** `feat/dev-agent-133` (off `origin/main` = current)
> **Issue:** #133 (child of #131 epic)
> **Date:** 2026-09-16

**Goal:** Build the Developer Agent that accepts task descriptions, writes code in sandboxed workers, modifies existing files guided by skeletal maps, writes unit tests, and iterates until tests pass.

**Architecture:** A seam (`DeveloperAgent`) with a `TaskAssignment` canonical payload. The agent orchestrates: scheduler → worker env (R2) → TDD cycle → metric emission → circuit breaker guard.

**Tech stack:** TypeScript, Vitest, existing Dark Factory R1+R2 seams.

---

## Acceptance Criteria (from #133)

| AC | Description |
|----|-------------|
| AC1 | Given a task description, when the agent runs in a sandbox, it produces code implementing the task + unit tests |
| AC2 | The agent iterates, modifying code until unit tests pass within sandbox (exit code 0) |
| AC3 | File modifications follow skeletal map guidance |
| AC4 | Only tools invoked: `git_clone`, `read_file`, `write_code`, `run_tests` |
| AC5 | Agent stops when all tests pass and reports completed task |

---

## Dependencies

- **R1 seams:** `StateStore` (track iteration state), `MetricsStore` (record fix cycles), `Dispatcher` (receive task)
- **R2 seams:** `WorkerProvider` (sandbox lifecycle), `CredentialBroker` (repo access)
- **NFRs:** convergence within bounded iterations, isolated sandbox, ~15min timeout per task

**RED:**
