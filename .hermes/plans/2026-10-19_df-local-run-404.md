# #404 — a local Dark Factory run is provisioned deliberately, not discovered by refusal

**Issue:** #404 (`enhancement`, `docs`) · **Branch:** `feat/df-local-run-404` · **Base:** `5aa08f9` (R2 #406 merged)

**Goal.** The local run path works, and every prerequisite was discovered by hitting its refusal — five runs, one
refusal each. This change makes the chain deliberate: one checked-in launcher that asserts every prerequisite and
reports **all** of them at once, owns the two things a run silently depends on (a target checkout as the working
directory, and a local control/run-history store), and refuses with one actionable block instead of an afternoon.

## What already exists, and what is actually missing

Re-visiting this issue after R2 merged changed two of its premises. Both make the work smaller and more consistent
than the text implies:

| #404 said | the repository actually has | what R1 does instead |
|---|---|---|
| ".env.local is NOT loaded by the runner" | `scripts/load-env.ts` exports `loadLocalEnv()`, and `df-membership.ts` + `seed-test-data.ts` already adopt it | the runner adopts the **same helper** — one import, no second loader |
| "a single checked-in launcher" | `scripts/sandbox-server-up.sh`, `df:sandbox-up` and `df:sandbox-smoke` already exist | the launcher **reuses** them rather than reimplementing the seam |

One item the issue does not yet contain, learned during the live E2E: **a parked run holds its issue's claim**. A
second run on the same issue is refused — *"the ledger already holds an active run (…, status 'blocked') … retire its
claim if the process is gone"* — and there is **no in-repo way to retire one**. That, plus reconciling the `df:running`
label a dead run leaves behind, is the same problem: *what a run leaves behind when it stops without finishing*. So it
is R2, not R1.

| release | branch | scope | why here |

## The decisions R1 makes

1. **Refuse with ALL the problems, not the first.** Five runs each produced one refusal. The preflight collects every
   missing prerequisite and prints one block: what is missing, the variable or step, and the exact command that fixes it.
2. **A hosted store URL is refused locally unless asked for by name.** Observed failure: `self-signed certificate in
   certificate chain` aborted the park, so a target that could not be justified could not even ask its question. A
   local run points at a local store; `--allow-remote-store` is the explicit override, and ADR 0039 still governs CA
   trust.
3. **The working directory is a checklist item, not folklore.** Discovery reads `process.cwd()`, so the launcher
   prepares a checkout of the TARGET repository and runs the child there (#405). The checkout must never persist the
   token: auth is injected per git command, and a test asserts the checkout's `origin` URL carries no credential.
4. **Secrets are read at runtime and never printed.** The launcher reports names and presence, never values, and the
   runner keeps failing closed on a missing provider key.
5. **The launcher does not code and does not merge.** A successful local run posts the plan and parks (#378 opt-in
   approval). The launcher says so in its final line, so a park is not mistaken for a hang.

## Validation

- **The acceptance is the end-to-end, not the unit tests.** On WebFeedPOC #169,
  `npm run df:local-run -- --repo ricardoblackskye/WebFeedPOC --issue 169` with NO hand-exported environment posts the
  plan on the issue and parks; and a second run refuses naming the claim holder in one line.
- **Fail-closed and complete:** with each prerequisite removed in turn, the launcher refuses BEFORE spawning the runner
  and names every missing item in a single block.
- **Backward compatible:** the runner still fails closed with no provider key, and adopting `loadLocalEnv` changes
  nothing when `.env.local` is absent.
- `tsc --noEmit`, the full suite, the doc-drift, ADR-index and env-coverage guards, and the local lint gate over the
  WHOLE diff file set (`git diff --name-only <base>..HEAD`).

## Risks

1. **A probe that hangs.** The Postgres and sandbox checks get short timeouts and report "not reachable" as a
   prerequisite problem. A run that needs a live database cannot be fully offline; the preflight makes that explicit
   rather than mysterious.
2. **The launcher drifting from the runner.** The preflight must assert what the runner actually requires. The
   variables are listed in ONE place so a divergence is a single edit, and the E2E is the proof that it still holds.
3. **Auto-cloning a target repository.** It writes only to a workspace directory, never to the user's own clone, and
   never persists a credential — asserted by task 3 rather than trusted.
4. **Scope creep into the store.** Retiring a claim is deliberately R2: it changes the ledger's API surface and needs
   its own design (expire versus delete, who may do it, what the ticket says afterwards).

## Out of scope

- Retiring a stale claim and reconciling labels (R2).
- The Architect's cwd behaviour itself (#405 is that code change; R1 supplies the correct working directory and
  documents the rule).
- Any change to approval semantics (#378 / ADR 0041) or to the deployed path.
