# Plan: #295 — capture and surface the agent git diff in runs detail view

Epic: #267 (Foundations towards UAT) · P1.
Follow-up to #272 (PR link already surfaced). One of the Dark Factory
`OUTCOME` artifacts, alongside tester output (#296) and reasoning/trace (#297).

## Goal

Record the developer-agent produced git diff on each run and render it
(collapsible) in the runs detail view, so a reviewer can see exactly what the
agent changed without leaving the board.

## Scope

In scope:

- Extend the run-history model to carry a sanitized git diff.
- Persist it in the postgres and sqlite stores.
- Capture the diff at the point the developer-agent finishes (the orchestrator
  or dispatch records the patch from the agent work tree).
- Render the diff (collapsible) in the runs detail view.
- Sanitize `DF_*` secrets from the diff before storage: redact, never store
  plaintext secrets. This honours the run-history no-raw-content principle.

Out of scope (separate issues): tester output (#296), reasoning/trace (#297).

## Current state

- `RunSummary` already carries `prUrl` (added for #272). The `OUTCOME` panel in
  `app/dark-factory/ui/components.tsx` renders it and is the intended home for
  this artifact.
- The developer-agent lives in `agent/lib/dark-factory/developer-agent.ts`. The
  git diff is produced by the agent in its work tree through the Eve runtime, not
  via `execSync` in this library. The exact capture point is confirmed in Task 3.
- `run-history.ts` validates and projects `RunSummary` / `RunEvent` through
  `toRunSummary` / `toRunEvent`, so any new field needs validation there.

## Approach (RED then GREEN, one commit pair per task)

### Task 1 — model

Add `gitDiff?: string` (already sanitized) to `RunSummary`. Validate it in
`toRunSummary` (size cap, no raw `DF_*` secrets). Unit tests RED then GREEN.

### Task 2 — stores

Persist `gitDiff` in postgres (migration plus row mapping) and sqlite (row
mapping). Store tests RED then GREEN.

### Task 3 — capture

Wire the orchestrator or dispatch to record the produced patch after the
developer-agent finishes, and sanitize `DF_*` secrets. Integration test RED
then GREEN.

### Task 4 — UI

Extend `OutcomeArtifacts` (or add a `DiffArtifact`) to render the diff in a
collapsible block. Component and page tests RED then GREEN.

### Task 5 — gate

Run `npm run typecheck`, the full `tests/dark-factory` suite, the full
`tests/dark-factory-ui` suite, and cspell on changed files. Push, open a PR,
and confirm CI is green before reporting done.

## Secret handling

- A `sanitizeDiff(raw)` helper redacts `DF_*` values (env assignments and URLs
  with credentials) before storage. Store only the sanitized string, never the
  raw patch.
- Unit-test the redactor against a fixture that contains fake `DF_*` secrets.

## Notes and risks

- Diffs can be large: cap the stored size (for example 64 KiB) and surface a
  "diff truncated" note when capped.
- Capture point: confirm whether the orchestrator or the developer-agent owns
  the work tree, so the diff is read from the correct path.
- This is larger than #272. If preferred, split into two releases: backend
  capture and storage first, then the UI. Say the word and I will split it.
