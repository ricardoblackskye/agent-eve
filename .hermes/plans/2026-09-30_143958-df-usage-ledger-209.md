# Dark Factory LLM Usage Ledger (#209) Implementation Plan

> **For Hermes:** implement task-by-task with `test-driven-development`
> (RED -> GREEN -> REFACTOR). This is release **R7.3** of epic #206.

**Goal:** record an append-only, provider-neutral ledger of per-call/per-task LLM
usage (tokens, cost, duration, model, run/PBI) and surface it as aggregates on
the operator dashboard.

**Architecture:** one canonical `UsageEvent` type plus a `UsageStore` seam with
an in-memory default, a local SQLite adapter and a Postgres/Supabase adapter,
chosen by `DF_USAGE_DRIVER` and mirroring the existing run-history seam. A
no-loss buffered decorator guarantees a ledger outage never fails the task.
Recording is OPT-IN and counts-only. Aggregates are computed by a pure query
module, exposed through one authenticated read-only route and one dashboard
panel.

**Tech Stack:** TypeScript, `node:sqlite` (local), `pg` (deployed / Supabase),
Vitest, Next.js App Router routes + React client panels, plain CSS.

## Decisions (settled with the user before planning)

1. **Recording is OPT-IN.** `DF_USAGE_DRIVER` unset => `InMemoryUsageStore`, no
   external writes. `postgres` / `sqlite` must be set explicitly, otherwise
   recording is a silent no-op. Enabling the feature cannot break a deployment.
2. **Privacy: counts only.** No prompt or completion text is ever stored.
3. **Honesty (#158):** an unmeasured value is ABSENT, never `0`; the dashboard
   renders `—`.
4. **No-loss (#140):** a usage-store outage must not fail the task.

## Scope boundary

- IN: canonical event, store seam + 3 drivers, no-loss buffering, aggregation,
  two call-site hooks, one read-only route, one dashboard panel, env docs.
- OUT: enforcing budgets/caps from the ledger (already delivered separately as
  cost governance); editing policy (R7.2 / #208); the orchestrator hook (#217).

**Step 1 — write the failing test**

```ts
import { describe, expect, it } from "vitest";
import {
  InvalidUsageEventError,
  MAX_USAGE_COST_USD,
  MAX_USAGE_LATENCY_MS,
  MAX_USAGE_TOKENS,
  toUsageEvent,
} from "../../agent/lib/dark-factory/usage-ledger";

const base = {
  runId: "run-1",
  taskType: "pr-review",
  model: "deepseek/deepseek-chat",
  ts: "2026-09-30T10:00:00.000Z",
};

describe("toUsageEvent", () => {
  it("omits unmeasured fields rather than zero-filling them", () => {
    const event = toUsageEvent({ ...base });
    expect(event).not.toHaveProperty("costUsd");
    expect(event).not.toHaveProperty("tokensIn");
    expect(event).not.toHaveProperty("durationMs");
  });

  it("keeps a measured zero as zero", () => {
    expect(toUsageEvent({ ...base, costUsd: 0 }).costUsd).toBe(0);
  });

  it("rejects a negative or absurd token count", () => {
    expect(() => toUsageEvent({ ...base, tokensIn: -1 })).toThrow(
      InvalidUsageEventError,
    );
    expect(() => toUsageEvent({ ...base, tokensOut: MAX_USAGE_TOKENS + 1 })).toThrow(
      InvalidUsageEventError,
    );
  });

  it("rejects a non-finite cost", () => {
    expect(() => toUsageEvent({ ...base, costUsd: Number.NaN })).toThrow(
      InvalidUsageEventError,
    );
    expect(() => toUsageEvent({ ...base, costUsd: MAX_USAGE_COST_USD + 1 })).toThrow(
      InvalidUsageEventError,
    );
  });

  it("rejects an empty runId, taskType or model", () => {
    expect(() => toUsageEvent({ ...base, runId: "  " })).toThrow(InvalidUsageEventError);
    expect(() => toUsageEvent({ ...base, taskType: "" })).toThrow(InvalidUsageEventError);
    expect(() => toUsageEvent({ ...base, model: "" })).toThrow(InvalidUsageEventError);
  });

  it("rejects a non-ISO timestamp", () => {
    expect(() => toUsageEvent({ ...base, ts: "yesterday" })).toThrow(InvalidUsageEventError);
  });

  it("rejects a pbiId that is not a positive safe integer", () => {
    expect(() => toUsageEvent({ ...base, pbiId: 0 })).toThrow(InvalidUsageEventError);
    expect(() => toUsageEvent({ ...base, pbiId: 1.5 })).toThrow(InvalidUsageEventError);
  });
});
```

**Step 2 — run it:** `npx vitest run tests/dark-factory/usage-ledger.test.ts`

**Step 3 — minimal implementation**

```ts
export interface UsageEvent {
  runId: string;
  pbiId?: number;
  taskType: string;
  model: string;
  tokensIn?: number;
  tokensOut?: number;
  costUsd?: number;
  durationMs?: number;
  ts: string;
}

export const MAX_USAGE_TOKENS = 2_000_000;
export const MAX_USAGE_COST_USD = 1000;
export const MAX_USAGE_LATENCY_MS = 86_400_000;

export class InvalidUsageEventError extends Error {
  constructor(message: string) {
    super(message);
    this.name = "InvalidUsageEventError";
  }
}
```

trim + require the three strings and the ISO `ts`; for each optional numeric

within `[0, max]`; absent stays absent).

## Task 2 — `UsageStore` seam + in-memory adapter

**Objective:** the write/read contract every driver implements.

**Files:**
- Create: `agent/lib/dark-factory/usage-store.ts`
- Test: `tests/dark-factory/usage-store.test.ts`

**Contract**

```ts
export interface UsageWriteResult {
  ok: boolean;
  mode: "live" | "blocked";
  providerId: string;
  event?: UsageEvent;
  error?: string;
}

export interface UsageReadResult<T> {
  ok: boolean;
  mode: "live" | "blocked";
  providerId: string;
  value: T | null;
  error?: string;
}

export interface UsageStore {
  id: string;
  record(event: UsageEvent): Promise<UsageWriteResult>;
  aggregate(query?: UsageQuery): Promise<UsageReadResult<UsageAggregate>>;
  close(): void | Promise<void>;
}
```

**RED cases:** valid event is stored and returns `ok:true` with the normalised
event; an invalid event THROWS (`InvalidUsageEventError`) because that is a
caller bug, whereas an unwritable store returns `ok:false` — the same split
documented in `metrics.ts`.

**GREEN:** `InMemoryUsageStore` holding `UsageEvent[]` plus a `getEvents()`
accessor for assertions.

**Commit** `feat(df): usage store seam and in-memory adapter`.

## Task 3 — No-loss buffered recorder

**Objective:** a ledger outage must never fail the task (#140 pattern).

**Files:**
- Modify: `agent/lib/dark-factory/usage-store.ts`
- Test: `tests/dark-factory/usage-store.test.ts`

**RED cases** (mirror the `FlakyStore` suite for `BufferedMetricsRecorder`):
- a store that rejects the write => `record()` returns `ok:false` AND the event
  is retained by `pending()`;
- `flush()` against a recovered store drains the buffer and returns `ok:true`;
- `flush()` against a still-failing store keeps every event and returns
  `ok:false` with a "still unsaved" message;
- the buffered re-send carries EVERY field (a shape that dropped `tokensIn`
  would silently lose tokens — the exact loss this decorator exists to prevent).

**GREEN:** `BufferedUsageRecorder implements UsageStore` wrapping any store, with
a `toInput`-style full-field re-send.

**Also add:** a `recordSafely(event)` helper that swallows ledger failures and
never throws, so call sites can record without risking the task. Document that
"never fails the caller" is the contract.

**Commit** `feat(df): no-loss buffered usage recording`.

## Task 7 — Aggregation query module

**Files:** Create `agent/lib/dark-factory/usage-query.ts`; test
`tests/dark-factory/usage-query.test.ts`.

**Objective:** counts and measured sums for a window, per model and per run.

```ts
export interface UsageQuery { from?: string; to?: string; runId?: string; model?: string }

export interface UsageAggregate {
  totals: { calls: number; tokensIn?: number; tokensOut?: number; costUsd?: number };
  byModel: Array<{ model: string; calls: number; costUsd?: number }>;
  byDay: Array<{ date: string; calls: number; costUsd?: number }>;
  byRun: Array<{ runId: string; calls: number; costUsd?: number }>;
  /** events that carried no measurement at all — shown as `—`, never 0 */
  unmeasured: number;
}
```

**RED cases:** inclusive `from` / exclusive `to` (reuse
`normalizeRunDateRange`); a window with no events returns zero calls and OMITS
the sum keys; an event with no cost does not drag the cost sum (measured-only
mean/sum — reuse the `meanOfMeasured` reasoning from `metrics.ts`); `unmeasured`
counts only events with neither tokens nor cost nor duration.

**Commit** `feat(df): usage aggregation queries`.

## Risks / open questions

1. **Duplication with the merged cost ledger.** The cost governance already
   stores `spent_usd`/`call_count` per (period, category). The usage ledger is
   the time-series record; the two must not be conflated. The ledger does NOT
   read or write `df_cost_budgets`.
2. **No home issue for the merged cost-governance work.** It is currently tracked
   by no issue (only PR #216). Flagged to the user; not actioned here.
3. **`isDeployedRuntime` duplication.** `run-history-provider.ts` holds a private
   copy. Task 4 should reuse rather than add a third divergent copy — extract to
   a shared module if that stays cheap, otherwise mirror it and note why.
4. **Token counts require the provider `usage` block.** Where a provider omits it,
   tokens stay absent by design (never estimated), so `byModel` token sums will
   under-report. Documented, not silently zero-filled.
