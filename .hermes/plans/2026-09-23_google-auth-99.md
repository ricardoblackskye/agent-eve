# Plan — #99: Google authentication for Eve Chat and web pages (custom OAuth)

**Issue:** [#99](https://github.com/ricardoblackskye/agent-eve/issues/99) _(still open; PR #177 never merged)_
**Branch:** `feat/google-auth-#99` (already rebuilt onto `origin/main` @ `1a4cda2`; contains only `app/google-auth.ts` + `tests/google-auth.test.ts`)

## Current state

The branch holds a **pure allow-list check** (`verifyGoogleChatAccess`, 9 passing tests) and nothing else. There is **no OAuth flow wiring**: no redirect, no token exchange, no session, no sign-in/out, no gate — and `verifyGoogleChatAccess` is **never called**. There is no prior plan.

App surface to protect:

- Pages: `/` (chat UI — `app/page.tsx` → `Chat`), `/architecture`, `/releasenotes`
- API: `/api/eve/v1/[...slug]` (Eve proxy), `/api/architecture`, `/api/releasenotes`, `/api/github/webhook` (**must stay public** — server-to-server, has its own signature check)

Stack: Next.js **16** (request interception file is **`proxy.ts`**, renamed from `middleware.ts`), app-router, ESM, Node 24, `withEve(nextConfig)` wrapper, Vercel. No auth deps today.

## Approach (agreed)

**Custom**: `google-auth-library` (server-side ID-token verification) + `jose` (Edge-safe signed session cookie). No framework, no DB, no Next-16 framework-compat risk.

## AC mapping

| AC                                            | Where                                                                                                  |
| --------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| Unauth user on Eve Chat → Google sign-in      | `proxy.ts` gate → 302 `/api/auth/google/start?next=`                                                   |
| Sign-in as allowed email → access granted     | callback → `verifyGoogleChatAccess` → session cookie                                                   |
| Other email → denied + 'unauthorized' message | callback → `/unauthorized` page                                                                        |
| Session expiry / sign-out → back to sign-in   | cookie `exp` + `/api/auth/signout` (clears cookie)                                                     |
| MUST Google-only, hardcoded email, no DB      | single provider; `ALLOWED_GOOGLE_EMAIL` (default `cuillinguy@gmail.com`)                               |
| MUST NOT expose chat pre-auth                 | gate covers `/`, `/architecture`, `/releasenotes`, `/api/eve`                                          |
| SHOULD HttpOnly session                       | `jose` HS256 cookie: HttpOnly, SameSite=Lax, Secure (prod), Path=/                                     |
| NFR ≤50ms check; server-side only; HTTPS      | local cookie verify (no network/DB); ID token verified server-side; Secure cookie + HTTPS redirect URI |

## Design

1. **`app/auth-config.ts`** — reads `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `GOOGLE_REDIRECT_URI` (optional; else derived from the request origin), `ALLOWED_GOOGLE_EMAIL` (default `cuillinguy@gmail.com`), `AUTH_SESSION_SECRET`, `AUTH_DEV_MODE` (default off).
2. **`app/google-auth.ts`** (extend, keep the existing function + tests) — allowed set becomes `[process.env.ALLOWED_GOOGLE_EMAIL || "cuillinguy@gmail.com"]`.
3. **`app/auth-session.ts`** — `createSessionToken({email, now, ttlMs, secret})` / `verifySessionToken(token, {now, secret})` via `jose` HS256. Session TTL e.g. 8h.
4. **`app/auth-oauth.ts`** — pure helpers: `createPkcePair()` (S256), `createState()`, `validateState(cookie, query)`, `buildGoogleAuthUrl({clientId, redirectUri, state, codeChallenge})`.
5. **Routes**
   - `app/api/auth/google/start/route.ts` — set short-lived HttpOnly `state` + `verifier` cookies, 302 → Google consent.
   - `app/api/auth/google/callback/route.ts` — validate `state`; `OAuth2Client.getToken(code)`; `verifyIdToken` (aud/iss/exp); map → `verifyGoogleChatAccess`; allowed → session cookie + redirect `next`; denied → `/unauthorized`.
   - `app/api/auth/signout/route.ts` — clear cookies, redirect `/`.
   - `app/api/auth/dev/route.ts` — **dev only, FAIL-CLOSED**: mints a session for a given email **only** when `AUTH_DEV_MODE=1` **and** `NODE_ENV !== "production"`; refuses otherwise. Enables local demo + e2e without real Google credentials (mirrors the `DF_RUNNER=local` prod guard).
   - `app/unauthorized/page.tsx` — 'You are not authorized to use Eve Chat'.
6. **`proxy.ts`** — verify the session cookie (jose, Edge-safe; **no** `google-auth-library` here); protect `/`, `/architecture`, `/releasenotes`, `/api/eve`; allow `/api/auth`, `/unauthorized`, `/api/github/webhook`, static. Unauth → 302 to start (pages) / 401 (API).
7. **Docs** — README auth section; `.env.example` rows (the `env-example-coverage` test fails if a referenced var is undocumented).

## Local demo (no real Google credentials needed)

- `AUTH_DEV_MODE=1 npm run dev` → `/` unauth redirects; `/api/auth/dev?email=cuillinguy@gmail.com` signs in → `/` loads; `email=someone.else@gmail.com` → `/unauthorized`.

- With your real client id/secret in `.env.local`, the real Google consent flow.

## Risks / decisions

- **`proxy.ts` in Next 16** — verify matcher + Edge runtime behaviour under the `withEve` wrapper; keep all Google network calls in Node route handlers.
- **Webhook must stay public** (`/api/github/webhook`) — an accidental gate would break Dark Factory.
- **Dev mode fail-closed** — never enabled in production.
- **Secrets**: `AUTH_SESSION_SECRET` generated by you; `GOOGLE_CLIENT_SECRET` never in code or chat.
- **Cookie `Secure`** on Vercel (HTTPS); localhost dev is HTTP so `Secure` is conditional on `NODE_ENV==="production"`.
- New deps: `google-auth-library`, `jose`.
